# 2026-10-16: type-the-chart-helper

## Problem / Motivation

The engine (`SuperconducTED/superconducted-noise-engine`) vendored the chart kit from
`brand/figures/` at `06f1959` as `superconducted.figures`. `roles.json` and the two Cryostat
styles went across byte for byte and are pinned by sha256 in the engine's
`tests/test_figures.py`, but the helper could not: the engine's `src/` is checked by
`mypy --strict`, and `superconducted_figures.py` had no annotations. So the engine carries
an annotated copy with four listed differences, and nothing catches the two copies drifting
apart. This change annotates the brand's own helper so the engine can vendor it unchanged.

## What changed

| File | One-sentence description |
| --- | --- |
| `brand/figures/superconducted_figures.py` | Every function and module constant annotated; `mono_ticks` tells a `Figure`, an `Axes` and an iterable of `Axes` apart by type; behaviour unchanged. |
| `docs/implementations/2026-10-16-type-the-chart-helper.md` | This record, including what it would take for the engine's copy to become byte-identical. |

## Implementation approach

Annotations only, plus one dispatch change:

- `use()` and `roles()` return `dict[str, Any]` (the roles hold strings, a list, an int and a
  dict, so a precise `TypedDict` would add a second copy of `roles.json`'s schema for no
  caller's benefit); `series()` returns `list[str]`; `band()` returns the `PolyCollection`
  that `fill_between` makes; `crisp()` and `measured()` return a `Line2D`; `band_handle()`
  a `Patch`; data arguments are numpy's `ArrayLike`; extra keyword arguments `Any`.
- `mono_ticks` is generic over its argument (`_Target`, bound to `Figure | Axes |
  Iterable[Axes]`) and returns it unchanged. It used `hasattr(target, "tick_params")` to
  spot an Axes; `isinstance(target, Axes)` is what a type checker can follow. Every Axes,
  subclasses included, takes the same branch as before.
- Local names in `band()` and `crisp()` (`xs`, `los`, `his`, `ys`) no longer rebind the
  parameters, because a parameter typed `ArrayLike` cannot be reassigned an `ndarray`
  under `--strict` without a cast.

The public API is untouched: `HERE` and `STYLES` stay strings, `style_path()` returns a
string, `PALETTES` holds all six options, `_DOC` keeps its name (`build_demos.py` reads it),
and every message is word for word the same.

## Design decisions

- **Typed here rather than only in the engine.** A typed copy in the engine alone means the
  brand's file and the engine's file differ forever, and a fix to one has to be ported by
  hand. Typing the source lets the engine pin the helper by hash like the other three files.
- **Formatted to the engine's ruff settings** (line length 100, its rule set and its
  formatter). The brand folder has no linter of its own, so this costs nothing here and is
  what a byte-identical copy needs to pass the engine's gates.
- **`dict[str, Any]` over a `TypedDict`.** See above; the roles are data, read by key.

### What convergence would cost the engine

With this commit the engine could keep the helper byte-identical. Three ways, in order of
preference:

1. **Vendor the file unchanged next to a small shim (recommended).** Ship
   `superconducted_figures.py` as is inside `superconducted/figures/`, rename the engine's two
   style files to the brand's palette-named copies (`superconducted-cryostat.mplstyle` and
   `-dark`, byte-identical in content to the generic ones), and keep a short `__init__.py`
   that re-exports the helper and refuses any palette but Cryostat. All four vendored files
   are then pinned by hash; the engine owns about 30 lines. A user sees one brand-flavoured
   message (`call superconducted_figures.use(<palette>) first`).
2. **Vendor the file as the package itself with all twelve styles.** No engine code at
   all, but the five palettes the owner did not choose become one argument away in every
   engine figure, which the brand README keeps only as the record of the choice.
3. **Keep the engine's annotated copy.** Nothing to do now, but its four differences stay
   hand-maintained and a brand fix to the helper reaches the engine only if someone ports it.

## Verification

From the repository root, with matplotlib 3.11.2 and numpy 2.4.4 (the throwaway venv
`C:\t-mpl` on the owner's machine):

- `python -I brand/figures/check_styles.py`: 46 of 46 checks passed, before and after this
  change, and in both runs all 26 demo files regenerated byte-identical to the committed ones,
  so no drawing changed.
- `mypy --strict --python-version 3.11 brand/figures/superconducted_figures.py`: no issues
  (mypy 1.20.2).
- With the engine's `pyproject.toml` as config: `ruff check` and `ruff format --check` on the
  file pass (ruff 0.15.12).
